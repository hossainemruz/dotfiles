# taskctl Workflow Gate

Use `taskctl` only for requests concerning the selected Task, research, planning, Step implementation, PR review, validation, progress, or Task artifacts. Do not invoke it for unrelated work. Use `taskctl step context` as the working projection for Step implementation, feedback, and acceptance; use `taskctl pr context` for PR review; use the broader `taskctl context` only when Task-level state or PR selection is required. Do not read all of `plan.md` when a projection contains the required context. Direct Step feedback is handled in conversation with `taskctl step revise`, validation, self-review, and resubmission—not `review.md`. A corrective Step created by `/review-pr` may be started only by the user's `/address-review` invocation, never `/next-step`. Explorers and executors must never run `taskctl`; their callers must pass complete working context or exact commands. Never scan the vault or edit `task.yaml` or the generated `plan.md` progress block. Create optional artifacts with `taskctl artifact ensure`, and make every lifecycle transition with `taskctl`. Preserve artifact structure and user prose. Keep repository changes separate from artifact and lifecycle updates.
